# QA 메모리 — 반복되는 함정

- RLS 매트릭스의 insert 칸: 대상 행이 이미 있으면 정책이 허용할 때 중복 키(23505)로 "판정 불가" 오류가 난다. setup에서 그 행을 먼저 지워 권한만으로 판정되게 한다(#16 `removeBusinessProfile`).
- `OpCase.setup`/`withActor` setup은 관리자(postgres)로 돈다. "서버가 처리한 상태"로 만들려면 setup 안에서 `set local role service_role` → 작업 → `reset role`. service_role은 auth 스키마 테이블에도 쓸 수 있다(shim).
- 상태를 바꾸는 setup을 쓰면 "준비 상태 확인" 테스트를 같이 둔다. setup이 아무것도 안 하면 차단 칸이 개발 뒤에도 원인 모를 실패로 남는다.
- 한 파일에 매트릭스가 여러 개면 최상위 `beforeAll`로 DB 하나를 띄우고 `describeRlsMatrix(m, { db: () => db })`로 넘긴다(매트릭스마다 DB를 띄우면 느리다).
- 컬럼 단위 판정은 매트릭스 밖에서 `attempt()`를 그대로 써서 판정 규칙(0행·42501 = 차단)을 맞춘다.
- 개발 전 인수 테스트에서 seed는 개발이 바꾼다. 판정용 행은 seed와 겹치지 않는 id로 `<이슈>-fixture.ts`에서 서버로 넣는다(#28). seed의 unique 쌍(예: enrollments 학생–트레이너)과 부딪히지 않게 사용자도 따로 만든다.
- 값 검사·정원·중복처럼 "막는 방법을 개발이 고르는" 조건은 `attemptWrite`(23xxx·42501·P0001·0행 = 거부)로 판정하고, 바른 값의 짝(허용)을 꼭 같이 둔다. `attempt`는 제약 오류를 던지므로 권한 칸에만 쓴다.
- `describeRlsMatrix`의 `title:`은 요구사항 추적 센서가 읽지 않는다(describe/it 문자열만 읽는다). ID를 세게 하려면 매트릭스 밖 describe/it 이름에도 넣는다(#28).
- 플러그인 훅은 /tmp 복사본에서도 QA의 마이그레이션 쓰기를 막는다. 구현 없이 인수 테스트를 미리 돌려 볼 수 없다. 준비 데이터가 바르다는 근거는 "준비 상태 확인" 테스트와 허용 짝으로 남긴다(#28).
- 판정 때 개발이 QA의 일반 테스트(qa-boundaries 등)를 고쳤으면 `git diff -U0 origin/main...HEAD -- <파일> | grep '^-'`로 지운 단언만 보고, 허용 목록이 정확히 일치(toEqual)로 남았는지와 늘어난 항목이 결정 범위인지 확인한다(#28).
- 배정·삭제 제한은 "풀기(null)"로 우회되는지도 본다. 완료 조건 밖이면 반려하지 않고 기획에 묻는다(#28 반 배정 해제 → 반 삭제).
- 판정용 일회성 시도는 `supabase/tests/scratch/`에 잠깐 두고 돌린 뒤 지운다. vitest 콘솔 출력은 grep에 안 잡히므로 값은 `expect(x).toBe("show")` 실패 메시지로 본다.
- 앞 묶음 버그 수정(#31)처럼 기존 테이블만 쓰는 조건은 새 묶음 fixture와 파일을 나눠 앞 묶음 fixture(`createBundle2Db`)로 쓴다. 새 테이블이 없어도 돌아서 개발 전에 "버그 칸만 실패, 허용 짝은 통과"를 확인할 수 있다(#32).
- 여러 단계 우회(배정 해제 → 반 삭제)는 `withActor` 안에서 단계마다 `savepoint`/`rollback to savepoint`로 시도하고 단계별 영향 행 수를 함께 단언한다(#32).
- fixture SQL 검증: /tmp 복사본 seed에 임시 DDL을 붙여 준비 데이터가 들어가는지만 본다. 복사본에서 `cd` 뒤 상대 경로로 seed를 쓰거나 `.claude/logs`에 쓰면 QA 훅이 막는다. 막히면 다시 시도하지 않고, 복사본에 남은 차단 로그는 보고에 적는다(레포 로그는 훅이 직접 쓰므로 그것만 커밋)(#32).
- 정책 본문 검사는 "private 함수를 부른다"까지 요구하지 않는다(#28 refund_requests처럼 다른 테이블 RLS를 거치는 exists도 허용). "enrollments·tickets·group_classes 직접 조회 없음"만 본다(#32).
- 같은 사람을 쓰는 다음 묶음은 앞 묶음 fixture 위에 쌓는다(`createBundle4Db` = `createBundle3Db` + 새 행, #35). 앞 fixture의 id·준비 작업을 re-export해서 쓴다.
- 테이블이 없을 때도 참인 단언(정책 for-loop, "컬럼 없음", "트리거 없음")은 개발 전에도 통과한다. 반드시 "정책이 있다"·"컬럼 일치" 같은 짝 테스트를 같이 두고 PR에 통과 수의 이유를 적는다(#35).
- 매트릭스 `attempt`는 트리거 거부(P0001)를 던진다. 클라이언트 칸의 시도 SQL은 RLS로 막히는 값(남의 id)만 쓰고, "본인 id로 남의 대상에 쓰기"는 `attemptWrite`로 따로 둔다(#35).
- 판정 시작 전 `git fetch origin '+refs/heads/<브랜치>:refs/remotes/origin/<브랜치>'`로 PR head를 직접 받는다. 그냥 `git fetch`로는 원격 브랜치가 갱신되지 않을 때가 있다(#35, head sha는 `gh api .../pulls/<n> --jq .head.sha`로 대조).
- 무결성 트리거를 security definer로 두면 BEFORE 트리거가 RLS보다 먼저 돌아 권한 없는 사람에게 오류 코드(23514 vs 42501)로 관계가 샌다. 반려 사유는 아니지만 판정 때 카탈로그(prosecdef·proconfig·실행 권한)와 함께 보고한다(#35).
- 오류 코드 누출 점검: insert만 본다. update·delete는 RLS using이 먼저 행을 걸러 권한 없는 사람에게 트리거가 돌지 않는다(0행). 누출은 "남의 id를 본인 칸이 아닌 소유 칸(trainer_id·author_id·student_id)에 넣는" insert에서 난다. SQLSTATE를 그대로 돌려주는 로컬 `outcome()`으로 정확한 코드를 단언한다(#38).
- 셸 표준 입력이나 heredoc에 마이그레이션 파일 이름이 들어가면 QA 훅이 그 파일을 고치는 것으로 읽고 막는다. PR·리뷰 글은 Write 도구로 파일을 만들어 `-F body=@파일`로 보낸다(#38).
- fixture SQL은 `supabase/tests/scratch/`의 임시 테스트에서 앞 묶음 DB에 임시 DDL을 `db.exec`로 넣고 FIXTURE_SQL(export)과 준비 작업을 돌려 미리 검증할 수 있다(마이그레이션 파일을 쓰지 않아 훅에 안 막힌다). 돌린 뒤 scratch는 지운다(#41).
- beforeAll(fixture)이 실패하면 vitest는 그 파일 테스트를 failed가 아니라 skipped로 센다. 개발 전 결과는 "failed + skipped / 전체"로 적는다(#41).
- 쓴 사람 컬럼이 없는 테이블(review_replies)의 "그 사람이 아니면 서버 insert도 실패" 조건은 service_role에 auth.uid()가 없어 DB가 판정할 수 없다. 테스트로 쓰지 않고 기획에 묻는다(#41).
- 기존 테이블 쓰기를 새 상태(이용 제한 등)로 막는 조건은 허용 짝을 "같은 시도 + 그 상태만 푼 setup"(liftG)으로 둔다. 다른 사람으로 짝을 두면 거부 원인이 제한인지 가리지 못한다(#45).
- 하네스 PR 판정: main 훅과 PR 훅에 같은 명령을 표준 입력 JSON으로 넣어 비교하고, main의 훅 테스트 파일을 PR 훅에 그대로 돌린다. 훅 우회 명령을 여러 줄 heredoc으로 넘기면 QA 세션의 훅에 막히므로 케이스는 Write로 /tmp 파일에 쓴다(#48).
- 훅 허용을 넓히는 PR은 "읽기 도구"로 본 명령의 경로 값 옵션(--cache-location, --generateTrace, --tsBuildInfoFile, coverage.reportsDirectory 등)과 쓰기 API를 감싼 print/log까지 우회 시도한다. 보호 경로가 든 /tmp 복사본은 rm -rf가 훅에 막히므로 새 디렉터리 이름으로 복사한다(#48).
- 허용 목록 훅을 판정할 때는 목록 안 명령의 위험한 하위 명령(gh alias·download·clone), 인자를 그대로 돌려주는 함수(str.strip·split·encode), 도구가 읽는 환경 변수(vitest UPDATE_SNAPSHOT)를 먼저 우회 시도한다(#48 3차).
- 글 자리(SINK) 허용 목록을 판정할 때는 함수 이름마다 "스트림·대상 없이 부르면 인자를 돌려주는가"를 확인한다(yaml.dump는 글을 돌려주고 json.dump는 None). 마지막 판정에서는 main에서도 허용되던 구멍(gh api PUT contents 등)을 반려 사유와 분리해 참고로만 적는다(#48 4차).
- 훅 PR 최종 판정은 마지막 수정 diff가 말한 범위(줄 수)와 같은지 `git show --stat`으로 먼저 확인하고, 우회 탐색은 그 diff 범위만 한다(#48 최종).
- 역할·기본 권한 검증은 `/usr/lib/postgresql/16/bin`에 임시 클러스터를 만들어 한다. root로는 initdb·pg_ctl이 안 되니 `runuser -u postgres`로 돌린다. superuser는 `supabase_admin`, `postgres`는 superuser가 아니게 만들고, 기본 권한은 `alter default privileges for role postgres`로 건다(#59).
- 기본 권한을 바꾸는 변경은 /tmp 복사본에서 shim의 기본 권한 줄을 빼고 인수 테스트 전체를 돌린다. 대조군(그 마이그레이션 제외)이 실패하는지도 함께 본다(#59).
- 설정 파일의 "안전장치" 주석은 외부 도구 문서로 확인한다. 예: Supabase CLI v3에서 `--include-seed`가 `[db.seed] enabled = false`를 무시한다(#59).
