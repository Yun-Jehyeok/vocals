# 개발 메모리 — 반복되는 함정

- 한 Bash 명령에 보호 경로 문자열(`tests/acceptance/`, `supabase/migrations/`, `docs/`)과 훅이 해석 못 하는 쓰기(`pnpm`, `python3` 스크립트 등)가 함께 있으면 훅(`developer.opaque-write`)이 막는다. 인수 테스트는 `cd /home/claude/vocals/supabase && pnpm exec vitest run 16-account-edit`처럼 파일 이름 필터로, PR 설명은 `/tmp`에 받아 Edit로 고친 뒤 `gh api -X PATCH … -F body=@파일`로 올린다(#16).
- 정책만 바꿀 때는 새 마이그레이션에서 `alter policy <이름> on <테이블> using (...) with check (...)`로 고친다. 이름·대상 역할이 그대로라 drop/create보다 안전하다(#16).
- 새 `private` 함수를 만들면 `supabase/tests/schema.test.ts`의 실행 권한 목록에도 더한다. anon 목록은 `trainer_profile_is_public` 하나여야 하므로 SECURITY DEFINER 함수는 authenticated·service_role에만 준다(#16).
- 본인 쓰기 정책에는 활성 판정 `(select private.is_active_user((select auth.uid())))`을 붙인다. 묶음 2 이후 테이블도 같다(#16, AUTH-07).
- 이 클론은 `remote.origin.fetch`가 없어 `origin/main`이 안 생긴다. `git fetch origin main:refs/remotes/origin/main`처럼 대상 ref를 적는다(#28).
- `supabase/tests/qa-boundaries.test.ts`(QA 작성, 보호 경로 아님)는 권한 카탈로그를 고정한다(예: authenticated 테이블 단위 쓰기는 DELETE 몇 개뿐). 테이블 단위 grant를 더하면 깨지므로 한 줄만 고치고 [보고]에서 QA 확인을 요청한다(#28).
- seed의 승인 트레이너(`11`)는 기존 테스트가 "학생 없는 다른 트레이너"로 쓴다. 수강 관계 더미는 다른 트레이너(`12`·`13`·`16`)에 둔다(#28).
- 위 opaque-write 차단은 `git add supabase/migrations/…`와 `pnpm exec prettier`를 `&&`로 묶어도 걸린다. 포맷 검사와 커밋은 늘 다른 Bash 호출로 한다(#32).
- seed 사용자 수는 schema.test가 고정한다(학생 2·트레이너 6·운영자 1). 새 수강 관계가 필요하면 기존 사용자로 만든다. 정지 트레이너(`16`)에 학생1을 붙이면 공개 범위 테스트가 바뀌므로 파일럿(`13`)을 쓴다(#32).
- 차감 행 수 = `total_sessions − remaining_sessions`를 seed 테스트가 본다. 환불된 수강권(remaining 0)에는 차감 행을 두지 않는다(#32).
- "끝난 수강권은 클라이언트가 못 고친다" 같은 규칙은 트리거에서 역할을 보지 말고 RLS using에 `status <> 'ended'`를 더한다. service_role은 RLS를 거치지 않아 서버 경로가 자동으로 열린다(#31).
- 자식 테이블 읽기는 `exists (select 1 from <부모> where ...)`로 부모 RLS를 그대로 거치게 하면 판정이 한 곳에 모인다(trainer_genres, refund_requests·refunds → tickets). 행 잠금이 필요한 private 함수는 `volatile`이어야 한다(stable에서 FOR UPDATE 불가)(#28).
- Postgres는 BEFORE 트리거 뒤에 RLS WITH CHECK를 본다. 클라이언트가 쓰는 테이블의 무결성 트리거가 쓰는 사람의 RLS로 읽으면, 권한 없는 사람의 바른 값 시도가 42501이 아니라 P0001로 끝나 매트릭스(attempt)가 판정을 못 한다. 그런 트리거 함수는 `security definer`(실행 권한은 아무에게도 안 줌)로 읽는다(#35).
- 새 테이블·enum을 만들면 `supabase/tests/schema.test.ts`의 `ERD_COLUMNS`·`DOMAIN_ENUMS`·실행 권한 목록, 테이블 단위 DELETE를 주면 `qa-boundaries.test.ts` 목록에 더한다(#35).
- `gh issue view`·`gh pr view`는 GraphQL이라 403이다. `gh api repos/Yun-Jehyeok/vocals/issues/<n>`·`.../issues/<n>/comments`·`.../pulls/<n>`(REST)로 읽는다(#35).
- definer 무결성 트리거가 RLS WITH CHECK보다 먼저 돌면 23514와 42501 차이로 관계가 드러난다. 그 앞에 security invoker 트리거를 두고 `row_security_active(tg_relid)`일 때만 정책과 같은 기준으로 42501을 낸다. definer 함수 안에서는 current_user가 함수 주인이라 RLS가 걸리는지 알 수 없다. 같은 시점 트리거는 이름 알파벳 순으로 돈다(#38).
- WHERE가 있는 UPDATE는 새 행도 SELECT 정책을 통과해야 한다(Postgres가 SELECT 정책을 WITH CHECK로 더한다). 가리기·나가기처럼 값이 바뀐 뒤에도 쓴 사람이 그 행을 읽을 수 있는지 SELECT 정책과 함께 본다(#41).
- "쓰는 사람이 그 대상을 읽을 수 있나"(신고 대상 등)는 security invoker인 `authorize_client_insert` 안에서 대상 테이블을 그냥 조회하면 쓰는 사람의 RLS가 그대로 걸린다. 판정을 따로 복제하지 않는다(#41).
- 인수 테스트의 "준비 상태 확인"이 테이블 전체를 집계하면 seed 더미와 부딪칠 수 있다(#41: 신고된 메시지가 있는 방 목록). seed를 테스트에 맞춰 비우지 말고 `[질문] 받는 역할: QA`로 올린다(#41).
- 기존 테이블 insert를 막는 새 제약(예: 제한 중 사용자의 메시지·후기 트리거)을 더하면 seed 순서가 걸린다. 막는 쪽 행(제한 줄)은 seed 맨 뒤, 막히는 행 다음에 넣는다(#45).
- 플러그인 0.6.0(#48)부터 `pnpm check`·`test`·`vitest run`·`prettier --check`와 gh·jq·`git commit -m`의 데이터 글자는 opaque-write 차단에 걸리지 않는다. `pnpm format`·`--write`·`-u`는 그대로다(#48).
- 인터프리터 표준 입력(`python3 - <<'EOF'`) 본문은 명령 규칙이 그대로 검사한다. 고치는 글에 push·--force·트레일러 글자가 있으면 막힌다(정상 동작). 그런 파일 수정은 Edit 도구로 한다. 단 `.claude/` 아래는 Edit도 승인이 필요하니 [보고] 메모리 칸으로 넘긴다(#48).
- 훅을 손볼 때 새로 허용하는 줄마다 "같은 명령의 다른 부분이 그 허용 뒤에 숨어 쓰지 않는가"를 main 훅과 비교해 확인한다. 실행(sh·xargs·`| sh`)이 같이 있으면 데이터도 코드다(#48 QA 반려).
- 훅에서 오탐을 줄일 때는 막을 목록을 늘리지 말고 허용할 형태를 목록으로 정한다(플래그·명령 허용 목록, 모르면 차단). 열거식 보강은 #48에서 QA 반려를 두 번 받았다.
- 훅 허용 목록에 명령 이름(gh 등)을 통째로 넣지 않는다. 하위 명령·플래그 단위로 넣고, 인자나 그 일부를 돌려주는 함수(strip·split 등)는 "글 자리"로 보지 않는다(#48 QA 반려 3차).
- 글 자리 목록에는 어떤 라이브러리로 불러도 결과가 None·참거짓·숫자인 함수만 넣는다. `dump`처럼 라이브러리마다 동작이 다른 이름은 넣지 않는다(#48 QA 반려 4차, `yaml.dump`).
- 개발 역할에서 Bash 명령 하나에 `docs/` 글자와 python heredoc 쓰기가 같이 있으면 훅이 막는다. 스크립트는 /tmp 파일로 따로 써서 실행하고, 커밋 메시지는 `git commit -F - <<'EOF'`로 쓴다(#52).
- 앱 테스트는 RNTL 14라 `render`·`renderRouter`가 비동기다. `await` 없이 부르면 "`render` function has not been called"로 실패한다(#56).
- 이 환경은 프록시가 api.expo.dev를 막아 `expo install --check`가 실패한다. `EXPO_OFFLINE=1`로 돌리고, 버전은 `npm pack expo@<버전>`의 `bundledNativeModules.json`에서 읽는다(#56).
- 개발의 스모크·단위 테스트 이름에 요구사항 ID를 넣으면 req-trace가 기준선에서 그 ID를 지우라고 실패한다. ID 추적은 QA 인수 테스트에 맡긴다(#56).
- Supabase CLI 3.x는 원격 반영·마이그레이션 목록·초기화 명령의 기본 대상이 로컬이다. 원격은 `--remote`를 붙인다(2.x는 `--linked`가 기본이었다)(#59).
- Supabase는 2026-10-30부터 public의 새 테이블·시퀀스에 anon·authenticated·service_role 기본 권한을 주지 않는다. 새 테이블은 클라이언트 권한을 명시 grant한다. service_role 기본 권한은 20261123120000이 복원한다(#59).
- 개발 훅은 `pnpm` 명령과 인수 테스트 경로가 한 Bash에 같이 있으면 막는다. 명령을 나눈다(#59).
- 훅은 로컬 DB를 대상으로 해도 Supabase CLI의 원격 반영 명령을 막는다(#59).
- 개발 역할에서 `pnpm test <이름>`에 `-t` 같은 플래그를 붙이면 보호 경로 글자와 함께 막힌다. 위치 인자로만 거르고(`pnpm test 56-app > /tmp/x.log`), 결과는 따로 grep한다(#56).
- jest-expo는 `expo-modules-core`를 doMock해 네이티브 모듈 대역을 준다. `resetModules` 뒤 실제 모듈을 다시 넣으면 expo-crypto 등이 "Cannot find native module"로 실패한다(#56).
- AsyncStorage 2.x는 jest에서 import만 해도 예외가 난다. 앱을 렌더하는 개발 테스트는 공식 대역(`…/jest/async-storage-mock`)을 `jest.mock`으로 넣는다(#56).
- Expo SDK 58은 URL·URLSearchParams 표준 구현을 전역에 넣는다. `react-native-url-polyfill`은 필요 없다(#56).
- PR이 main과 충돌하면(`mergeable_state: dirty`) GitHub가 pull_request CI를 돌리지 않고 pull_request_target(Harness guard)만 돈다. push 뒤 CI가 안 보이면 mergeable_state부터 본다(#56).
- CI는 로컬보다 느려 jest 기본 5초 한도를 넘는 렌더 테스트가 있다. 앱 렌더 테스트는 파일 안에 `jest.setTimeout(30_000)`을 둔다(#56).
- worktree에서 일해도 훅 로그의 브랜치는 세션 cwd(메인 체크아웃)의 브랜치다(명령 안의 cd /tmp/wt-… 무관). 로그가 다른 브랜치 이름 파일에 섞일 수 있다(#61).
- 트레일러 글자가 든 테스트·문서는 Bash heredoc(python)이 아니라 Edit·Write로 고친다. 테스트에서는 글자를 쪼개지 말고 상수 하나에 담아 Edit로 쓴다(#61).
- 임시 vocals 모양 저장소(plugin.json 마커+docs/)는 개발 역할로 rm -rf가 막힌다. 실험 저장소에는 docs/를 만들지 않거나 마커 없이 만든다(#61).
